#### 1. Estrutura de Configuração

Cada entidade do domínio terá uma classe de configuração correspondente implementando `IEntityTypeConfiguration<TEntity>`:

```csharp
// Entidade de Domínio
public class Projeto
{
    public int Id { get; set; }  // INTEGER com IDENTITY no banco
    public string Nome { get; set; }
    public string Descricao { get; set; }
    public string? IdIup { get; set; }
    public int? StatusId { get; set; }
    public virtual Status? Status { get; set; }
}

// Configuração de Mapeamento
public class ProjetoConfiguration : IEntityTypeConfiguration<Projeto>
{
    public void Configure(EntityTypeBuilder<Projeto> builder)
    {
        // Configurações detalhadas
    }
}
```

#### 2. Configuração de Tabela

**Observação:** O schema padrão do projeto já está configurado no `ApplicationDbContext`. Não é necessário especificá-lo em cada configuração.

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Nome da tabela com comentário para documentação do banco
    // Schema "a11732" já está configurado centralmente no DbContext
    builder.ToTable("projeto",
        t => t.HasComment("Armazena informações principais de projetos"));
}
```

#### 3. Configuração de Chave Primária

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Chave primária simples com auto-incremento (Identity Column)
    builder.HasKey(p => p.Id)
        .HasName("pk_proj");

    builder.Property(p => p.Id)
        .HasColumnName("proj_cd_projeto")
        .HasColumnType("integer")
        .ValueGeneratedOnAdd()  // Gera INTEGER GENERATED BY DEFAULT AS IDENTITY
        .IsRequired()
        .HasComment("Identificador único do projeto");

    // Chave primária composta (quando aplicável em tabelas associativas)
    builder.HasKey(pp => new { pp.ProjetoId, pp.DisciplinaId })
        .HasName("pk_projeto_disciplina");
}
```

#### 4. Configuração de Propriedades

**Regra obrigatória:** Todas as propriedades **devem** ter:

1. `HasColumnName()` - Nome da coluna no banco
2. `HasColumnType()` - Tipo explícito da coluna (quando relevante)
3. `HasComment()` - Comentário descritivo

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Configuração de coluna com restrições e validações
    builder.Property(p => p.Nome)
        .HasColumnName("proj_nm_projeto")
        .HasColumnType("varchar(100)")
        .HasMaxLength(100)
        .IsRequired()
        .HasComment("Nome do projeto");

    // Configuração de descrição com validação de tamanho
    builder.Property(p => p.Descricao)
        .HasColumnName("proj_ds_projeto")
        .HasMaxLength(500)
        .HasColumnType("varchar")
        .IsRequired()
        .HasComment("Descrição do projeto");

    // Configuração de identificador externo (nullable)
    builder.Property(p => p.IdIup)
        .HasColumnName("proj_cd_iup")
        .HasMaxLength(50)
        .HasColumnType("varchar")
        .IsRequired(false)
        .HasComment("Identificador IUP do projeto");

    // Configuração de tipo do projeto
    builder.Property(p => p.TipoProjeto)
        .HasColumnName("proj_tp_projeto")
        .HasMaxLength(100)
        .HasColumnType("varchar")
        .IsRequired(false)
        .HasComment("Tipo do projeto");

    // Configuração de chave estrangeira
    builder.Property(p => p.StatusId)
        .HasColumnName("proj_cd_status")
        .HasColumnType("integer")
        .IsRequired(false)
        .HasComment("Código do status do projeto");

    // Configuração de gerências (strings)
    builder.Property(p => p.GerenciaProjeto)
        .HasColumnName("proj_nm_gerencia")
        .HasMaxLength(100)
        .HasColumnType("varchar")
        .IsRequired(false)
        .HasComment("Nome da gerência do projeto");
}
```

#### 5. Configuração de Índices

**Nomenclatura:** Todos os índices devem seguir os padrões definidos no **DT-003** (lowercase).

##### 5.1 Índice Simples

**Padrão:** `in_<mnemônico>_<texto_significativo>` (conforme DT-003)

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Índice para melhorar performance de consultas por nome
    builder.HasIndex(p => p.Nome)
        .HasDatabaseName("in_proj_nome");

    // Índice para consultas por ID IUP
    builder.HasIndex(p => p.IdIup)
        .HasDatabaseName("in_proj_iup");

    // Índice para consultas por tipo de projeto
    builder.HasIndex(p => p.TipoProjeto)
        .HasDatabaseName("in_proj_tipo");
}
```

##### 5.4 Índice de Chave Estrangeira (FK)

**Padrão:** `in_fk_<tabela_pai_mnem>_<tabela_filho_mnem>_<descrição>` (conforme DT-003)

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Índice para FK de status (melhora performance de JOINs)
    builder.HasIndex(p => p.StatusId)
        .HasDatabaseName("in_fk_stat_proj_status");

    // Índice para FK de fase
    builder.HasIndex(p => p.FaseId)
        .HasDatabaseName("in_fk_fase_proj_fase");
}
```

##### 5.5 Índice com Filtro (Partial Index)

**Padrão:** `in_<mnemônico>_<texto_significativo>` com filtro WHERE

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Índice apenas para projetos com IUP informado (economiza espaço)
    builder.HasIndex(p => p.IdIup)
        .HasDatabaseName("in_proj_iup_ativo")
        .HasFilter("proj_cd_iup IS NOT NULL");

    // Índice para consultas por nome apenas de projetos em andamento
    builder.HasIndex(p => new { p.Nome, p.StatusId })
        .HasDatabaseName("in_proj_nome_status")
        .HasFilter("proj_cd_status = 1");

    // Índice único de IUP apenas para registros com gerencia informada
    builder.HasIndex(p => p.IdIup)
        .HasDatabaseName("in_proj_iup_gerencia")
        .IsUnique()
        .HasFilter("proj_nm_gerencia IS NOT NULL");
}
```

##### 5.7 Check Constraints

**Padrão:** `ck_<mnemônico>_<descrição>` (conforme DT-003)

**Método recomendado:** `.HasCheckConstraint()` na configuração da entidade (EF Core 5.0+)

#### Configuração com HasCheckConstraint

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // 1. Check para valores de tipo de projeto (enum/status)
    builder.Property(p => p.TipoProjeto)
        .HasColumnName("proj_tp_tipo")
        .HasMaxLength(1)
        .HasColumnType("char")
        .IsRequired(false)
        .HasComment("Tipo do projeto: D=Desenvolvimento, M=Manutenção, P=Pesquisa, I=Infraestrutura");

    builder.HasCheckConstraint("ck_proj_tipo",
        "proj_tp_tipo IN ('D', 'M', 'P', 'I')");

    // 2. Check para garantir que descrição não seja vazia
    builder.Property(p => p.Descricao)
        .HasColumnName("proj_ds_projeto")
        .HasMaxLength(500)
        .HasColumnType("varchar")
        .IsRequired()
        .HasComment("Descrição do projeto (não pode ser vazia)");

    builder.HasCheckConstraint("ck_proj_descricao",
        "LENGTH(TRIM(proj_ds_projeto)) > 0");

    // 3. Check para valores de orçamento positivos
    builder.Property(p => p.ValorOrcamento)
        .HasColumnName("proj_vl_orcamento")
        .HasPrecision(15, 2)
        .HasColumnType("numeric")
        .IsRequired(false)
        .HasComment("Valor do orçamento do projeto (deve ser > 0)");

    builder.HasCheckConstraint("ck_proj_orcamento",
        "proj_vl_orcamento > 0");

    // 4. Check para IUP (formato específico)
    builder.Property(p => p.IdIup)
        .HasColumnName("proj_cd_iup")
        .HasMaxLength(50)
        .HasColumnType("varchar")
        .IsRequired(false)
        .HasComment("Identificador IUP com formato específico");

    builder.HasCheckConstraint("ck_proj_iup_formato",
        "proj_cd_iup ~ '^[A-Z0-9-]+$'");
}

// Exemplo para tabela com validação de datas relacionadas
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    builder.Property(p => p.DataInicio)
        .HasColumnName("proj_dt_inicio")
        .HasColumnType("date")
        .IsRequired()
        .HasComment("Data de início do projeto");

    builder.Property(p => p.DataFim)
        .HasColumnName("proj_dt_fim")
        .HasColumnType("date")
        .IsRequired(false)
        .HasComment("Data de término do projeto");

    // Check constraint envolvendo múltiplas colunas
    builder.HasCheckConstraint("ck_proj_datas",
        "proj_dt_fim IS NULL OR proj_dt_fim >= proj_dt_inicio");
}

// Exemplo para validações complexas com múltiplas condições
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    builder.Property(p => p.ValorOrcamento)
        .HasColumnName("proj_vl_orcamento")
        .HasPrecision(15, 2)
        .HasColumnType("numeric")
        .IsRequired(false)
        .HasComment("Valor total do orçamento");

    builder.Property(p => p.ValorExecutado)
        .HasColumnName("proj_vl_executado")
        .HasPrecision(15, 2)
        .HasColumnType("numeric")
        .HasDefaultValue(0)
        .IsRequired()
        .HasComment("Valor executado do projeto");

    builder.Property(p => p.ValorSaldo)
        .HasColumnName("proj_vl_saldo")
        .HasPrecision(15, 2)
        .HasColumnType("numeric")
        .IsRequired(false)
        .HasComment("Saldo disponível do projeto");

    // Check constraint complexa com múltiplas validações
    builder.HasCheckConstraint("ck_proj_valores", @"
        proj_vl_orcamento IS NULL OR proj_vl_orcamento >= 0
        AND proj_vl_executado >= 0
        AND proj_vl_executado <= COALESCE(proj_vl_orcamento, proj_vl_executado)
        AND (proj_vl_saldo IS NULL OR proj_vl_saldo = proj_vl_orcamento - proj_vl_executado)
    ");
}
```

#### Quando Usar Check Constraints

✅ **USE quando:**

- Necessário garantir integridade mesmo com acesso direto ao banco
- Validações simples de valores (IN, BETWEEN, >, <)
- Proteção contra scripts SQL externos
- Compatibilidade com sistemas legados

❌ **NÃO USE quando:**

- Validações complexas com lógica de negócio
- Necessário fornecer mensagens amigáveis aos usuários
- Validações que dependem de dados de outras tabelas (use triggers)
- Regras que mudam frequentemente

##### 5.8 Unique Constraints

**Padrão:** `un_<mnemônico>_<descrição>` (conforme DT-003)

**Observação:** Unique constraints são criadas automaticamente quando usamos `.HasIndex().IsUnique()`, mas podemos nomear explicitamente.

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Unique constraint via índice único (recomendado no EF Core)
    builder.HasIndex(p => p.Nome)
        .HasDatabaseName("un_proj_nome")
        .IsUnique();

    // Unique constraint via propriedade (alternativa)
    builder.Property(p => p.IdIup)
        .HasColumnName("proj_cd_iup")
        .HasMaxLength(50)
        .HasColumnType("varchar")
        .IsRequired(false)
        .HasComment("Identificador IUP do projeto. Unique: in_proj_iup");

    builder.HasIndex(p => p.IdIup)
        .HasDatabaseName("un_proj_iup")
        .IsUnique();

    // Unique constraint composta (IUP + Gerencia)
    builder.HasIndex(p => new { p.IdIup, p.GerenciaProjeto })
        .HasDatabaseName("un_proj_iup_gerencia")
        .IsUnique();
}
```

**Nomenclatura gerada:**

- Índice único simples: `un_proj_nome`, `un_proj_iup`
- Índice único composto: `un_proj_iup_gerencia`

##### 5.9 Default Constraints

**Padrão:** Configurado via `HasDefaultValue()` ou `HasDefaultValueSql()` (EF Core não nomeia explicitamente)

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Default com valor constante (booleano)
    builder.Property(p => p.Ativo)
        .HasColumnName("proj_in_ativo")
        .HasColumnType("boolean")
        .HasDefaultValue(true)
        .IsRequired()
        .HasComment("Indicador se o projeto está ativo (default: true)");

    // Default com função SQL
    builder.Property(p => p.DataCriacao)
        .HasColumnName("proj_dt_criacao")
        .HasColumnType("timestamp")
        .HasDefaultValueSql("CURRENT_TIMESTAMP")
        .IsRequired()
        .HasComment("Data e hora de criação do registro (default: CURRENT_TIMESTAMP)");

    // Default com valor calculado
    builder.Property(p => p.DataPrevisaoTermino)
        .HasColumnName("proj_dt_previsao_termino")
        .HasColumnType("timestamp")
        .HasDefaultValueSql("CURRENT_TIMESTAMP + INTERVAL '1 year'")
        .IsRequired(false)
        .HasComment("Data prevista de término (default: 1 ano após criação)");

    // Default para CHAR(1) indicador de prioridade
    builder.Property(p => p.Prioridade)
        .HasColumnName("proj_in_prioridade")
        .HasMaxLength(1)
        .HasColumnType("char")
        .HasDefaultValue('N')  // 'N' = Normal, 'A' = Alta, 'B' = Baixa
        .IsRequired()
        .HasComment("Prioridade do projeto (N=Normal, A=Alta, B=Baixa). Default: N");
}
```

**Observações:**

- EF Core não permite nomear explicitamente defaults (ex: `df_proj_in_ativo`)
- PostgreSQL gera nomes automáticos no formato `<tabela>_<coluna>_default`

#### 6. Configuração de Relacionamentos

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Configuração da FK antes do relacionamento
    builder.Property(p => p.StatusId)
        .HasColumnName("proj_cd_status")
        .HasColumnType("integer")
        .IsRequired(false)
        .HasComment("Código do status do projeto");

    // Relacionamento N:1 (Vários projetos pertencem a um status)
    builder.HasOne(p => p.Status)
        .WithMany(s => s.Projetos)
        .HasForeignKey(p => p.StatusId)
        .HasConstraintName("fk_stat_proj")
        .OnDelete(DeleteBehavior.Restrict);

    // Relacionamento N:1 (Vários projetos pertencem a uma fase)
    builder.HasOne(p => p.Fase)
        .WithMany(f => f.Projetos)
        .HasForeignKey(p => p.FaseId)
        .HasConstraintName("fk_fase_proj")
        .OnDelete(DeleteBehavior.Restrict);

    // Relacionamento 1:N (Um projeto tem várias disciplinas)
    builder.HasMany(p => p.Disciplinas)
        .WithOne(d => d.Projeto)
        .HasForeignKey(d => d.ProjetoId)
        .HasConstraintName("fk_proj_disc")
        .OnDelete(DeleteBehavior.Restrict);

    // Relacionamento N:N (via tabela de junção explícita)
    builder.HasMany(p => p.Membros)
        .WithMany(m => m.Projetos)
        .UsingEntity<ProjetoMembro>(
            j => j.HasOne(pm => pm.Membro)
                  .WithMany()
                  .HasForeignKey(pm => pm.MembroId)
                  .HasConstraintName("fk_membro_proj_membro"),
            j => j.HasOne(pm => pm.Projeto)
                  .WithMany()
                  .HasForeignKey(pm => pm.ProjetoId)
                  .HasConstraintName("fk_proj_proj_membro"),
            j =>
            {
                j.ToTable("projeto_membro");
                j.HasKey(pm => new { pm.ProjetoId, pm.MembroId })
                 .HasName("pk_proj_membro");
            });
}
```

#### 8. Configuração de Conversores de Valor

Para tipos complexos simples, recomenda-se o uso de Value Objects (padrão DDD) com conversão explícita:

```csharp
// Value Object de Localização Geográfica
public class LocalizacaoGeografica
{
    public string Cidade { get; private set; }
    public string Estado { get; private set; }
    public string Pais { get; private set; }

    public LocalizacaoGeografica(string cidade, string estado, string pais)
    {
        Cidade = cidade;
        Estado = estado;
        Pais = pais;
    }
}

// Configuração de conversão
public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Conversão de enum para string
    builder.Property(p => p.StatusProjeto)
        .HasColumnName("proj_st_status")
        .HasColumnType("varchar(20)")
        .HasMaxLength(20)
        .HasConversion<string>()
        .IsRequired()
        .HasComment("Status do projeto (enum convertido para string)");

    // Conversão de Value Object para propriedades individuais
    builder.OwnsOne(p => p.Localizacao, localizacao =>
    {
        localizacao.Property(l => l.Cidade)
            .HasColumnName("proj_nm_cidade")
            .HasColumnType("varchar(100)")
            .HasMaxLength(100)
            .HasComment("Cidade onde o projeto é executado");

        localizacao.Property(l => l.Estado)
            .HasColumnName("proj_sg_estado")
            .HasColumnType("varchar(2)")
            .HasMaxLength(2)
            .HasComment("Sigla do estado (UF)");

        localizacao.Property(l => l.Pais)
            .HasColumnName("proj_sg_pais")
            .HasColumnType("varchar(3)")
            .HasMaxLength(3)
            .HasComment("Código ISO do país (3 caracteres)");
    });
}
```

### Organização de Arquivos

As configurações de mapeamento do Entity Framework Core devem ser organizadas dentro da camada de infraestrutura do projeto, especificamente no diretório **`Persistencia/Configuracoes`**:

```
src/
└── ProjSub.Infraestrutura/
    └── Persistencia/
        ├── Configuracoes/              ← DIRETÓRIO DE CONFIGURAÇÕES DE MAPEAMENTO
        │   ├── UsuarioConfiguration.cs
        │   ├── PerfilConfiguration.cs
        │   ├── DepartamentoConfiguration.cs
        │   ├── AuditableEntityTypeConfiguration.cs
        │   └── ...
        └── Migrations/
```

**⚠️ IMPORTANTE**: Todas as classes de configuração de mapeamento (implementações de `IEntityTypeConfiguration<T>`) devem ser criadas **exclusivamente** no diretório `Persistencia/Configuracoes`. Esta padronização:

- Facilita a localização das configurações de mapeamento
- Mantém a separação clara entre lógica de domínio e persistência
- Permite que o Entity Framework descubra automaticamente as configurações via `ApplyConfigurationsFromAssembly`
- Garante consistência na estrutura do projeto

### Boas Práticas Gerais

#### 1. Performance

```csharp
public void Configure(EntityTypeBuilder<Projeto> builder)
{
```

## 9. Mapeamento de Views e Materialized Views

### 9.1 Views (vw\_)

**Padrão:** `vw_<domínio>_<descrição>` (conforme DT-003 seção 7)

Views são usadas para consultas read-only complexas, relatórios e agregações.

```csharp
// Entidade de leitura para View
public class ProjetoAtivoView
{
    public int Id { get; set; }
    public string Nome { get; set; }
    public string Descricao { get; set; }
    public string StatusNome { get; set; }
    public int TotalDisciplinas { get; set; }
}

// Configuration para View
public class ProjetoAtivoViewConfiguration : IEntityTypeConfiguration<ProjetoAtivoView>
{
    public void Configure(EntityTypeBuilder<ProjetoAtivoView> builder)
    {
        // Mapeamento para view existente
        builder.ToView("vw_projeto_ativo", "a11732");

        // Entidade read-only (sem tracking)
        builder.HasNoKey(); // Se view não tem PK definida
        // OU
        builder.HasKey(v => v.Id); // Se view tem PK

        // Mapeamento de colunas
        builder.Property(v => v.Id)
            .HasColumnName("proj_cd_projeto")
            .HasColumnType("integer");

        builder.Property(v => v.Nome)
            .HasColumnName("proj_nm_projeto")
            .HasColumnType("varchar(100)");

        builder.Property(v => v.Descricao)
            .HasColumnName("proj_ds_projeto")
            .HasColumnType("varchar(500)");
    }
}

```

### 9.2 Materialized Views (mv\_)

**Padrão:** `mv_<domínio>_<descrição>` (conforme DT-003 seção 12)

Materialized Views são usadas para consultas pesadas com refresh periódico.

```csharp
// Entidade para Materialized View
public class DashboardProjetoMV
{
    public int Ano { get; set; }
    public int Mes { get; set; }
    public string StatusNome { get; set; }
    public int TotalProjetos { get; set; }
    public decimal OrcamentoTotal { get; set; }
    public int ProjetosAtrasados { get; set; }
}

// Configuration
public class DashboardProjetoMVConfiguration : IEntityTypeConfiguration<DashboardProjetoMV>
{
    public void Configure(EntityTypeBuilder<DashboardProjetoMV> builder)
    {
        // Mapeamento para materialized view
        builder.ToTable("mv_dashboard_projeto", "a11732");

        // Chave composta para MV
        builder.HasKey(m => new { m.Ano, m.Mes, m.StatusNome });

        // Mapeamento de colunas
        builder.Property(m => m.Ano)
            .HasColumnName("ano")
            .HasColumnType("integer");

        builder.Property(m => m.Mes)
            .HasColumnName("mes")
            .HasColumnType("integer");

        builder.Property(m => m.StatusNome)
            .HasColumnName("stat_nm_status")
            .HasColumnType("varchar(50)");

        builder.Property(m => m.TotalProjetos)
            .HasColumnName("total_projetos")
            .HasColumnType("integer");
    }
}

// Registro no DbContext
public DbSet<DashboardProjetoMV> DashboardProjetos { get; set; }
```

### 11.1 Conversores Comuns

#### Enum para Integer

```csharp
public enum TipoProjeto { Desenvolvimento = 1, Manutencao = 2, Pesquisa = 3, Infraestrutura = 4 }

builder.Property(p => p.Tipo)
    .HasColumnName("proj_tp_tipo")
    .HasColumnType("integer")
    .HasConversion<int>()  // Armazena valor numérico
    .IsRequired()
    .HasComment("Tipo do projeto (1=Desenvolvimento, 2=Manutenção, 3=Pesquisa, 4=Infraestrutura)");
```

#### Enum para String

```csharp
builder.Property(p => p.Tipo)
    .HasColumnName("proj_tp_tipo")

    .HasMaxLength(20)
```

#### Enum para String com Mapeamento Customizado (Recomendado)

```csharp
public enum TipoProjeto
{
    Desenvolvimento,
    Manutencao,
    Pesquisa,
    Infraestrutura
}

public void Configure(EntityTypeBuilder<Projeto> builder)
{
    // Dicionário de mapeamento enum <-> código
    var tipoConverter = new ValueConverter<TipoProjeto, string>(
        // Conversão: Enum -> String (para o banco)
        v => v switch
        {
            TipoProjeto.Desenvolvimento => "D",
            TipoProjeto.Manutencao => "M",
            TipoProjeto.Pesquisa => "P",
            TipoProjeto.Infraestrutura => "I",
            _ => throw new ArgumentException($"Tipo inválido: {v}")
        },
        // Conversão: String -> Enum (do banco para aplicação)
        v => v switch
        {
            "D" => TipoProjeto.Desenvolvimento,
            "M" => TipoProjeto.Manutencao,
            "P" => TipoProjeto.Pesquisa,
            "I" => TipoProjeto.Infraestrutura,
            _ => throw new ArgumentException($"Código de tipo inválido: {v}")
        });

    // Configuração da propriedade com conversor customizado
    builder.Property(p => p.Tipo)
        .HasColumnName("proj_tp_tipo")
        .HasColumnType("char(1)")
        .HasMaxLength(1)
        .HasConversion(tipoConverter)
        .IsRequired()
        .HasComment("Tipo do projeto: D=Desenvolvimento, M=Manutenção, P=Pesquisa, I=Infraestrutura");

    // Check constraint para garantir valores válidos no banco
    builder.HasCheckConstraint("ck_proj_tipo",
        "proj_tp_tipo IN ('D', 'M', 'P', 'I')");
}
```

**Vantagens desta abordagem:**

✅ **Compacto**: Armazena apenas 1 caractere em vez do nome completo do enum  
✅ **Legível**: Códigos de uma letra são fáceis de entender em queries SQL  
✅ **Seguro**: Check constraint previne valores inválidos no banco  
✅ **Tipo-seguro**: Aplicação trabalha com enum fortemente tipado  
✅ **Padrão corporativo**: Segue convenção BDIEP de indicadores (in\_)

## Consequências

### Positivas

✅ **Separação de responsabilidades**: Entidades de domínio ficam livres de preocupações de persistência

✅ **Manutenibilidade**: Cada entidade tem sua configuração isolada e fácil de localizar no diretório `Persistencia/Configuracoes`

✅ **Reutilização**: Configurações base podem ser herdadas para entidades semelhantes através de classes abstratas

✅ **Testabilidade**: Entidades puras facilitam testes unitários
✅ **Consistência**: Padrão único de configuração em todo o projeto seguindo normas corporativas
✅ **Evolução**: Facilita refatorações e mudanças no modelo de dados
✅ **Code Review**: Mudanças em configurações são facilmente identificáveis

### Negativas

⚠️ **Overhead inicial**: Requer criação de classes de configuração adicionais
⚠️ **Curva de aprendizado**: Equipe precisa conhecer Fluent API do EF Core
⚠️ **Código adicional**: Mais arquivos para manter no projeto

### Neutras

🔄 **Performance**: Sem impacto significativo comparado a outras abordagens
🔄 **Migrations**: Funciona normalmente com qualquer abordagem de configuração

## Conformidade

Esta decisão está alinhada com:

- **Padrões SQL Petrobras (PE-2TIC-00319)**: Nomenclatura de colunas, tabelas e constraints
- **Clean Architecture**: Separação entre domínio e infraestrutura
- **DDD (Domain-Driven Design)**: Entidades de domínio livres de detalhes de persistência
- **Princípio da Responsabilidade Única (SRP)**: Cada classe tem uma única responsabilidade

## Notas de Implementação

### Checklist de Configuração de Entidade

Ao criar uma nova configuração de entidade no diretório `Persistencia/Configuracoes`, verificar:

- [ ] Classe implementa `IEntityTypeConfiguration<TEntity>`
- [ ] Classe está no diretório correto: `ProjSub.Infraestrutura/Persistencia/Configuracoes`
- [ ] Nome de tabela e esquema configurados
- [ ] Chave primária configurada com nome de constraint
- [ ] Todas as propriedades têm tipo de coluna explícito e tamanho máximo definido
- [ ] Propriedades obrigatórias marcadas com `IsRequired()`
- [ ] Índices criados para chaves estrangeiras
- [ ] Índices criados para campos frequentemente consultados
- [ ] Relacionamentos configurados com nome de constraint
- [ ] Comentários adicionados em tabelas e colunas relevantes
- [ ] Nomenclatura segue padrão corporativo PE-2TIC-00319
- [ ] Configuração será descoberta automaticamente via `ApplyConfigurationsFromAssembly`
